REQUISITOS DE DESPLIEGUE - SIGGO (Guardia OIG)
==============================================

Guia breve para el equipo que suba la aplicacion a un servidor.


1. REQUISITOS DEL SERVIDOR
--------------------------
- Python 3.10 o superior
- MySQL 8.x
- Acceso para instalar dependencias: pip install -r requirements.txt


2. BASE DE DATOS
----------------
1. Crear la base de datos (por defecto "guardiaoig").
2. Ejecutar el script "schema.sql" completo.

IMPORTANTE: schema.sql crea, ademas de las tablas, la VISTA "resumen_guardias".
Si esa vista no existe, varias paginas (/asistencias, /guardias, /mis_asistencias, /inicio)
fallan con Error 500.


3. VARIABLES DE ENTORNO
-----------------------
Crear un archivo .env (o variables del sistema) con:

- SECRET_KEY        (OBLIGATORIA)  cadena larga y aleatoria. Sin ella la app no arranca.
- DB_HOST           (obligatoria)  ejemplo: localhost          (default: localhost)
- DB_USER           (obligatoria)  usuario de la base de datos
- DB_PASSWORD       (obligatoria)  clave de la base de datos
- DB_NAME           (opcional)     ejemplo: guardiaoig         (default: guardiaoig)
- DB_PORT           (opcional)     ejemplo: 3306               (default: 3306)

NOTA RAILWAY: si la app se despliega en Railway con el plugin "MySQL", Railway
inyecta automaticamente MYSQLHOST, MYSQLPORT, MYSQLUSER, MYSQLPASSWORD y
MYSQLDATABASE. El modulo "conexion.py" lee esas variables como respaldo de DB_*,
por lo que NO hace falta definir DB_* manualmente (usara mysql.railway.internal
por red interna, que es lo mas rapido). Para desarrollo LOCAL contra la misma BD
de Railway, define en .env el host publico (altaria.proxy.rlwy.net) y puerto 55443.

- DB_TIMEZONE       (opcional)     ejemplo: -05:00             (default: -05:00)
- FORCE_HTTPS       (recomendado)  true                        (default: false)
- PORT              (opcional)     ejemplo: 5000               (default: 8080)
- WAITRESS_THREADS  (opcional)     ejemplo: 8                  (default: 8)
- UPLOAD_FOLDER     (opcional)     ruta de archivos Excel      (default: uploads)
- FOTOS_FOLDER      (opcional)     ruta de fotos de perfil     (default: static/fotos)
- GEMINI_API_KEY    (solo si usan analisis con IA)
- GEMINI_MODEL      (opcional)     ejemplo: gemini-2.5-flash   (default: gemini-2.5-flash)
- RATE_LIMIT_STORAGE (opcional)    ejemplo: redis://localhost:6379/0  (default: memory://)
                                   Usar redis:// solo si la app corre en varios workers/replicas.
                                   Si se usa redis, se requiere un servidor Redis y el paquete
                                   "redis" (ya incluido en requirements.txt).
- LOG_DIR           (opcional)     carpeta de logs            (default: logs)
- LOG_LEVEL         (opcional)     DEBUG/INFO/WARNING/ERROR   (default: INFO)
                                   Los logs se guardan en LOG_DIR/app.log con rotación (10 MB, 5 respaldos).
- SMTP_USER         (opcional)     correo organizacional remitente (ej. notificaciones@oigperu.com)
- SMTP_PASSWORD     (opcional)     contraseña de aplicación (App Password) de Microsoft 365
- SMTP_FROM         (opcional)     remitente visible (si se deja vacío usa SMTP_USER)
- SMTP_HOST         (opcional)     default: smtp.office365.com
- SMTP_PORT         (opcional)     default: 587
- ALERTA_VACACIONES_INTERVALO_SEG (opcional) intervalo (segundos) de la alerta
                                   automatica diaria de vacaciones (default: 86400 = 24h)
- ALERTA_VACACIONES_ARRANQUE_SEG (opcional) retraso inicial antes de la primera
                                   comprobacion (default: 60)

Generar SECRET_KEY con:
python -c "import secrets; print(secrets.token_hex(32))"


4. ARRANQUE
-----------
pip install -r requirements.txt
python main.py

La app usa Waitress como servidor (no requiere gunicorn). Escucha en 0.0.0.0:PORT.

PUERTO: nginx.conf hace proxy a 127.0.0.1:8080, que coincide con el default de
main.py (PORT=8080). Si usan otro puerto, definir PORT o ajustar proxy_pass.


5. HTTPS Y NGINX
----------------
- Usar el nginx.conf incluido (ajustar server_name y rutas del certificado).
- Certificado gratis con Let's Encrypt: certbot --nginx -d tudominio.com
- FORCE_HTTPS=true para cookies seguras y HSTS.


6. CARPETAS CON PERMISOS DE ESCRITURA
-------------------------------------
Asegurar permisos de escritura para el usuario que ejecuta la app:

- uploads/          (archivos de informes/Excel)
- static/fotos/     (fotos de perfil)

Hacer backup de ambas carpetas junto con la base de datos.


7. SEGURIDAD
------------
- NO subir el archivo .env al repositorio (ya esta en .gitignore).
- SECRET_KEY larga y secreta.
- HTTPS activo en produccion.


8. CORREO DE NOTIFICACIONES (SMTP Microsoft 365 / Exchange)
-------------------------------------------------------------
La app envia correos de notificacion a los fiscalizadores (por ejemplo, al
registrar, editar o eliminar una compensacion o unas vacaciones). Para que
funcionen se necesita una cuenta de correo ORGANIZACIONAL (mismo dominio que los
usuarios, @oigperu.com) y su contraseña de aplicación. No usar una cuenta personal.

El área de TI debe proporcionar:
1. Una cuenta de correo remitente, ej. notificaciones@oigperu.com
2. La "contraseña de aplicación" (App Password) de Microsoft 365 para esa cuenta.
   NO es la contraseña normal de inicio de sesión de la cuenta.

Configurar en .env (o variables del sistema):
- SMTP_USER     = notificaciones@oigperu.com
- SMTP_PASSWORD = (contraseña de aplicación)
- SMTP_FROM     = (opcional, si se omite usa SMTP_USER)

Generar la contraseña de aplicación:
https://account.live.com/proofs/manage/additional
(Requiere tener activada la verificación en dos pasos en la cuenta de Microsoft.)

IMPORTANTE:
- Si SMTP_USER / SMTP_PASSWORD quedan vacíos, la app NO envía correos pero sigue
  funcionando con normalidad (solo registra un aviso en los logs).
- El dominio del remitente (SMTP_FROM) debe coincidir con el dominio de la
  organización (@oigperu.com) para que los correos no se vean como spam.

Ademas de las notificaciones por evento, la app ejecuta una tarea automatica
diaria que avisa por correo a los administradores cuando hay fiscalizadores
habilitados para tomar vacaciones o proximos a habilitarse (15 dias). El
intervalo y el retraso inicial se controlan con ALERTA_VACACIONES_INTERVALO_SEG
y ALERTA_VACACIONES_ARRANQUE_SEG (ver seccion 3).
